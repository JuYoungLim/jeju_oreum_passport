# 오름오름 — 제주 오름 수첩

오름 10곳을 찜하고 방문 도장을 남기는 웹앱입니다. 회원가입 없이 익명 수첩을 만들고, 비밀 복구 코드로 같은 기록을 다시 열 수 있습니다.

## 로컬 실행

Node.js 22 이상에서 로컬 서버는 추가 설치 없이 실행됩니다. Blob 관련 테스트와 배포에는 의존성 설치(`pnpm install`)가 필요합니다.

```sh
node scripts/serve.mjs
```

브라우저에서 http://localhost:5173 을 여세요. 첫 접속 시 개인 수첩이 자동으로 만들어집니다. 기존 localStorage의 찜·방문 기록이 있다면 처음 만든 수첩으로 옮깁니다. 서버에 수첩이 성공적으로 연결된 뒤 기존 브라우저 기록을 제거합니다.

```sh
node --test tests/*.test.mjs
node scripts/build.mjs
node scripts/serve.mjs --dist
```

`--dist`도 동일한 로컬 서버와 저장소를 사용합니다. 포트가 사용 중이면 기존 서버를 종료하거나 PowerShell에서 `$env:PORT = '5174'`를 지정하고 실행하세요.

## 수첩 사용법

1. 접속하면 수첩이 자동으로 만들어집니다. 기존 찜하기·방문 완료는 수첩에 저장됩니다.
2. 화면 위 **복구 코드 · 수첩 불러오기**를 누릅니다.
3. **내 복구 코드 발급받기**를 눌러 코드를 복사하고 안전한 곳에 보관합니다.
4. 다른 브라우저에서 같은 서버에 접속한 뒤 **기존 수첩 불러오기**에 코드를 입력합니다.
5. 같은 찜·도장이 나타납니다. 이전 수첩과 기록을 합치지는 않습니다.

복구 코드는 발급 직후에만 표시됩니다. 재발급하면 이전 코드는 즉시 무효가 되지만 이미 연결된 브라우저의 세션은 유지됩니다. 코드를 가진 사람은 그 수첩을 열고 수정할 수 있으므로 공유하지 마세요. 쿠키와 복구 코드를 모두 잃으면 복구할 수 없습니다. 접속 쿠키와 서버 세션은 발급 시점부터 90일간 유효합니다.

## 저장 구조

- `data/oreums.json`: 공개 오름 기본 정보 10곳. 이름·지역·소개·위치·공식 출처 등.
- `.local-data/notebooks.json`: 로컬 서버의 비공개 수첩 저장소. Git과 빌드 결과에서 제외합니다.
- 브라우저: `oreum_session` HttpOnly / SameSite=Strict 쿠키. 복구 코드나 접근 토큰을 localStorage에 저장하지 않습니다.
- 서버 저장소: 수첩 UUID, 오름별 찜·방문 상태, 복구 코드 SHA-256 해시, 세션 토큰 해시·만료 시간. 이메일과 비밀번호는 받지 않습니다.

수첩에 저장하는 오름 기록은 `{ "id": "saebyeol", "favorite": true, "visited": false }` 형태입니다. 무작위 32바이트로 만든 복구 코드·세션 토큰은 원문을 저장하지 않습니다. 사람의 비밀번호가 아니므로 고엔트로피 토큰용 해시를 사용합니다.

JSON 변경은 단일 프로세스의 순차 처리와 임시 파일 작성 후 교체로 저장합니다. 한 필드씩 변경하여 동시에 다른 오름을 저장할 때 배열 전체를 덮어쓰지 않습니다. 같은 필드의 동시 변경은 마지막으로 처리된 요청을 따릅니다. 저장 실패 시 성공한 것처럼 화면을 바꾸지 않습니다.

## API

| 경로 | 메서드 | 동작 |
| --- | --- | --- |
| `/api/notebook` | GET | 쿠키에 연결된 수첩 조회 |
| `/api/notebook` | POST | 수첩 생성, 최초 로컬 기록 가져오기 |
| `/api/notebook/records` | PATCH | 내 수첩의 오름 한 필드 변경 |
| `/api/notebook/recovery` | POST | 비밀 복구 코드 발급·재발급 |
| `/api/notebook/restore` | POST | 코드 검증 후 새 세션 쿠키 발급 |

요청마다 세션을 검증하며 사용자 ID를 보내서 다른 수첩을 고를 수 없습니다. 쓰기 요청은 같은 출처와 JSON 형식을 검사합니다. 복구 시도는 IP 기준 분당 10회, 익명 수첩 생성은 분당 20회로 제한합니다. 제한 상태는 프로세스 메모리이며 재시작하면 초기화됩니다. 개인 데이터 응답은 `private, no-store`입니다. 서버 소스와 로컬 저장 파일은 정적 URL로 제공하지 않습니다.

## 로컬 검증 범위와 배포

로컬 실행과 Vercel 배포용 소스를 함께 제공합니다. 실제 Vercel 배포 및 운영 저장소 접근 확인은 별도로 필요합니다.

로컬 서버는 `127.0.0.1`에만 바인딩합니다. 같은 컴퓨터의 다른 브라우저에서 복구 기능을 시험할 수 있습니다. `localhost`와 `127.0.0.1`도 쿠키가 분리되므로 두 주소로 시연할 수 있습니다. 휴대폰 등 외부 기기에서 현재 로컬 주소로 접속하는 것은 지원하지 않습니다.

### Vercel Blob 배포 준비

대상 저장소 이름은 **jeju-oreum-passport-blob**입니다. 저장소를 **Private**으로 생성하고 **Connect to Project**로 오름 앱 프로젝트에 연결하세요. Production/Preview 중 사용할 환경도 선택합니다.

이름은 표시용이며 접근 자격 증명이 아닙니다. Vercel이 연결 과정에서 제공하는 실제 BLOB_STORE_ID와 OIDC 인증 또는 서버 전용 BLOB_READ_WRITE_TOKEN으로 SDK가 저장소에 접근합니다. 비밀 토큰을 GitHub, 브라우저 코드, 채팅에 넣지 마세요. .env.example에는 빈 예시만 있습니다.

- api/notebook.js, api/notebook/[action].js: Vercel Node Functions 진입점
- server/runtime.mjs: 배포 환경에서 Private Blob 저장소를 사용하며 Secure 쿠키 발급
- server/blob.mjs: Private 전용 읽기·쓰기, 캐시를 우회한 최신 읽기, ETag 조건부 저장
- Production은 oreum/production/v1/notebooks.json, Preview는 oreum/preview/v1/notebooks.json을 사용하여 운영 기록과 분리

소규모 시연용으로 수첩별 레코드를 하나의 비공개 JSON에 모아 저장합니다. 다른 인스턴스가 먼저 수정하면 최신 내용을 읽고 최대 8회 재시도합니다. 요청 제한도 같은 저장소에 보관합니다. 사용자 수와 기록이 커지면 전체 파일 읽기·쓰기 비용이 늘어나므로 사용자별 파일과 인덱스 구조 또는 데이터베이스로 변경해야 합니다.

Vercel Functions가 카탈로그 JSON을 포함하도록 vercel.json을 설정했습니다. 의존성을 설치한 뒤 기존 build 명령으로 정적 화면과 API를 함께 배포합니다. 로컬 서버는 계속 디스크 JSON을 사용하며, 로컬 기록은 Blob으로 자동 이전되지 않습니다.

실제 저장소 접근·프로젝트 연결·클라우드 배포는 아직 확인하지 않았습니다. Blob SDK 모의 테스트로 경합 처리와 Private 옵션을 검증합니다. 배포 후 실제 수첩 생성, 복구, 동시 저장을 확인해야 합니다.

## 검증

`tests/notebook.test.mjs`는 익명 사용자 격리, 기록 유지, 복구·코드 재발급, 비밀값 원문 미저장, 동시 갱신, 권한·출처 검사, 요청 제한을 검사합니다. `tests/state.test.mjs`는 카탈로그와 화면의 기록·필터 로직을 검사합니다.

소개는 제주특별자치도와 비짓제주 자료를 요약했으며 상세 화면에서 원문을 볼 수 있습니다. 풍경은 직접 작성한 SVG 일러스트입니다.
